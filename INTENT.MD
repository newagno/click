# INTENT.MD: CryptoSnake Marathon Bot (Architecture, Diagnostics & Roadmap for Model Argon)

Цей документ створено для передачі моделі **Argon** (та іншим моделям аналізу й міркування). У ньому зафіксовано повний контекст проєкту, історію оптимізацій, вирішені проблеми та поточний головний бар'єр — фізику маневрування та ухилення від дрібних ворогів на довгих дистанціях (марафон 3–4 години, мета: **100,000–160,000+ монет**, топ-10 / топ-1 сезону).

## 2. Архітектура та стек технологій

```
                                  [ Python Runner (bot.py) ]
                                             │
                       SeleniumBase UC-Mode (Chrome, non-headless)
                                             │
                        ┌────────────────────┴────────────────────┐
                        ▼                                         ▼
            [ Browser Window DOM ]                    [ Injected JS Radar Loop ]
            - Cloudflare Turnstile                    - 100ms requestAnimationFrame/eval
            - #cs-hud, #cs-dead, #cs-run-warning     - Raycasting (12 променів, 4 дистанції)
            - WP account & local storage              - Turbo Vacuum Boost (Space)
                                                      - Hard Evade (ухилення від зіткнень)
                                                                  │
                                                                  ▼
                                                      [ WebSocket / HTTP API ]
                                                      - proto.request / proto.send
                                                      - Actions: start, checkpoint, finish
                                                      - Server TTL: 60s
```

* **Runner:** Python 3.12+ / 3.14, бібліотека `seleniumbase` у режимі `uc=True` (Undetected ChromeDriver).
* **Режим запуску:** **Тільки GUI (non-headless)**. Запуск у `--headless` суворо заборонений — Cloudflare Turnstile детектує `outerWidth/outerHeight = 0` і повертає `captcha_failed`.
* **JS Injection:** Функція `ensure_radar_injected()` інжектує радар у контекст сторінки один раз, перехоплює об'єкт гри `window.__CryptoSnake`, прототипи `VerifiedRun.prototype` (`proto.request`, `proto.send`, `proto.start`, `proto.abandon`).
* **Тактова частота:** JS-радар обчислює фізику кожні ~100 мс (10 FPS оновлення напрямку `targetAngle`, імпульсів швидкості `Space` та захисних маневрів).

## 3. Вирішена інфраструктура: Мережа та Верифікація (Патч v3.9.11)

> [!IMPORTANT]
> **НЕ ЗМІНЮВАТИ ТА НЕ ЛАМАТИ ЛОГІКУ `proto.request` ТА `proto.send`!**
> Цей блок був джерелом багів `run_closed` та `checkpoint_sequence` у версіях v3.9.4–v3.9.10 і був остаточно стабілізований у патчі **v3.9.11** (коміт `bb4a233`).

### Реалізований механізм імунітету (рядки 760–830 у `src/snake/bot.py`):
1. **Нейтралізація `abandon`:**
   - Перехоплено `window.navigator.sendBeacon` — виклики з `action: abandon` блокуються.
   - Події `pagehide` та `visibilitychange` заблоковані, `document.hidden` примусово повертає `false`.
   - `proto.abandon` перезаписано на порожній `async function() { return { ok: true }; }`.
2. **Ідемпотентний захист від `checkpoint_sequence` у `proto.request`:**
   - Таймаути чекпоінтів: 2 спроби по 24с: `[24000, 24000]`.
   - Якщо сервер повернув `checkpoint_sequence` (на будь-якій спробі `attempt >= 0`): це означає, що запит насправді дійшов до сервера, і поточний номер `seq` уже записаний у БД.
   - Бот повертає валідну відповідь:
     ```javascript
     return {
         ok: true,
         recovered: true,
         seq: committedSeq,
         checkpoint: (payload && payload.checkpoint) || this.checkpoint || 'ok'
     };
     ```
     *Примітка:* `checkpoint` зобов'язаний бути непорожнім, інакше нативний клієнт `cryptosnake.min.js` викине помилку regex-перевірки: `!/^[a-f0-9]{64}$/.test(...) => bad_checkpoint_response`.
3. **М'який відкат `this.seq` у `proto.send`:**
   - Перед кожним викликом зберігаються: `const prevSeq = this.seq; const prevCheckpoint = this.checkpoint;`.
   - При нефатальній помилці (мережевий таймаут тощо):
     `this.seq = prevSeq; this.checkpoint = prevCheckpoint; this.invalid = false;`
   - Блоку `#cs-run-warning` примусово виставляється `.hidden = true; .textContent = '';`.

**Результат v3.9.11:** За понад 2.5 години безперервної гри та 900+ чекпоінтів жодного банера `#cs-run-warning` та 0 втрат верифікації.

## 5. Анатомія трьох дефектів алгоритму Hard Evade

Код Hard Evade розташований у `src/snake/bot.py` (рядки 1515–1565):

### Дефект #1: Пастка пологого кута 16° (`absDelta = 0.28 rad`)
* **Механіка:** У масиві `candidateDeltas = [0, 0.28, -0.28, 0.55, -0.55, 0.82, -0.82, 1.12, -1.12, 1.45, -1.45, 1.75, -1.75]`, кут `0.28 rad ≈ 16°`.
* **Чому обирається 16°:**
  У формулі вартості:
  ```javascript
  var cost = 14.0 * dScore + towardEnemyPen + shallowPenalty + trapPenalty + flipPenalty + goalWeight * angleDiff + 0.22 * absDelta + wallPenalty;
  ```
  `shallowPenalty` зараз активується лише при:
  `((headingDanger >= 3 || closeEmergency) && absDelta < 0.75)`
  де `closeEmergency = (minEnemyDist < 98 && raycastDanger >= 1)`.
  Якщо ворог знаходиться на дистанції 100–160px і наближається під кутом, `headingDanger` може бути `<= 2`, а `closeEmergency` ще `false`. У результаті `shallowPenalty = 0.0`.
  Оскільки кут 16° має мінімальні `absDelta` (0.28) та `angleDiff` (відхилення від цільової їжі/кластера), алгоритм віддає перевагу 16° замість рішучого маневру на 45°–60°. Дрібний ворог на високій швидкості долає цю дистанцію за 300–400 мс і врізається в голову змійки.

### Дефект #2: Злам траєкторії (Flip) на 90° перед самим носом
* **Механіка:**
  Якщо бот ухиляється вправо (наприклад, `+47°`), але правий промінь зачіпає будь-яку перешкоду на дистанції 280px (`dScore = 1`), штраф становить `14.0 * 1 = 14.0`.
  Штраф за зміну знаку повороту на протилежний: `flipPenalty = 4.2`.
  Оскільки `14.0 > 4.2`, бот миттєво відкидає правий поворот і обирає протилежний лівий сектор (`-90°` / `-1.57 rad`), де `dScore = 0`.
* **Наслідок:**
  При масі 1200–1600 змійка має значну довжину тіла та радіус голови. Миттєвий злам курсу на 90° підставляє шию або бік прямо під зустрічний вектор ворога.

### Дефект #3: Блокування кута `__evadeLockAngle` на 480 мс
* **Механіка:**
  Коли бот здійснює маневр, він виставляє замок на 480 мс:
  `window.__evadeLockUntil = nowMs + 480; window.__evadeLockAngle = safestAngle;`
  Якщо на першому тику було обрано слабкий кут 16°, бот утримує цей неефективний вектор майже пів секунди, ігноруючи динамічне зближення ворога з 140px до 70px.

### Дефект #4: Нерівність швидкостей (Кінематика легких і важких змійок)
* У рушії `cryptosnake.min.js` лінійна швидкість змійки обернено пропорційна масі: змійки масою 50–100 рухаються значно швидше, ніж наша змійка масою 1500+.
* Радіус повороту великої змійки значно більший. Для неї різкий поворот на 90° (`1.57 rad`) неефективний — найбільш обтічними та швидкими є кути **35°–60°** (`0.60–1.05 rad`).

## 7. Конкретні напрямки оптимізації для Argon

### 1. Елімінація 16° при зближенні з ворогом:
- Якщо `minEnemyDist < 160` або `headingDanger >= 2` або `raycastDanger >= 3`:
  повністю виключати з розгляду або накладати критичний штраф (+15.0) на кути `|delta| < 0.45 rad` (~25°).
- Залишати мінімальним кутом відвороту **32°–50°** (`0.55–0.85 rad`).

### 2. Захист від згубного фліпу (Асиметричний `flipPenalty`):
- Якщо бот уже ухиляється в певний бік (`prevSign !== 0`) і `minEnemyDist < 160`:
  `flipPenalty` має бути **не менше 18.0** (щоб перебити `14.0 * dScore` від дальньої перешкоди dScore=1).
- Зміна знаку дозволяється **виключно** якщо попередній напрямок веде прямо в небезпеку рівня 4 (`dScore === 4`).

### 3. Нелінійна шкала загрози променів (`dangerCost` замість `14.0 * dScore`):
- Зараз: `dScore=1` (перешкода на відстані 288px) коштує 14.0, стільки ж скільки перехід між lv.2 і lv.3.
- Пропонується:
  - `dScore = 0`: вартість 0.0
  - `dScore = 1` (дистанція 288px): вартість 3.5 – 5.0 (не повинна змушувати бота кидатися під зустрічного ворога)
  - `dScore = 2` (дистанція 200px): вартість 15.0
  - `dScore = 3` (дистанція 120px): вартість 35.0
  - `dScore = 4` (дистанція 60px): вартість 80.0+

### 4. Динамічний `maxTurnRad` за масою:
- Для великої змійки (`meMass > 800`): обмежити максимальний поворот за 1 кадр до `1.15 rad` (~65°), щоб уникнути «підгинання шиї» та бокового заносу на 90°.
- Для середньої змійки (`250 <= meMass <= 800`): дозволяти до `1.35 rad`.
- На дистанції критичного зближення (`minEnemyDist < 50`): екстремальний відворот.

### 5. Скорочення або скасування `__evadeLockUntil` при загрозі:
- Якщо `minEnemyDist < 130` і поточний замок утримує небезпечний або слабкий кут — миттєво скидати замок: `window.__evadeLockUntil = 0`.

## 8. Протокол верифікації для будь-яких правок

Перед здачею змін обов'язково виконати перевірки в оточенні Windows:

1. **Синтаксична перевірка:**
   ```powershell
   .\venv_new\Scripts\python.exe -m py_compile src/snake/bot.py
   ```
2. **Запуск тестового набору:**
   ```powershell
   .\venv_new\Scripts\python.exe -m pytest tests/ -x -q
   ```
3. **Перевірка відсутності регресій у тестах звітності:**
   ```powershell
   .\venv_new\Scripts\python.exe -m pytest tests/test_snake_reporting.py -v
   ```
4. **Git Commit & Push:**
   Фіксувати зміни з детальним описом у commit message та пушити у гілку `main`.
